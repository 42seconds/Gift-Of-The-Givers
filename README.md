# Gift of the Givers – Web App + Azure Functions

Visual Studio solution `gift_of-the_givers.slnx` contains two projects:

| Project | Type | Purpose |
|---|---|---|
| `gift_of-the_givers.csproj` | ASP.NET Core Razor Pages (.NET 8) | The existing prototype web app (donations, volunteers, employee dashboard) |
| `GiftOfTheGivers.Functions/GiftOfTheGivers.Functions.csproj` | Azure Functions v4, .NET 8 isolated worker, **HTTP trigger** | Extends the web app with serverless functions |

```
gift_of-the_givers/
├── gift_of-the_givers.slnx              ← open this in Visual Studio
├── gift_of-the_givers.csproj            ← web app
├── Services/AzureFunctionsClient.cs     ← web app → function calls
├── Pages/Donation/Certificate.*         ← calls GenerateTaxCertificate
├── Pages/Employee/Dashboard.*           ← calls LogProjectUpdate / GetProjectUpdateLog
└── GiftOfTheGivers.Functions/
    ├── Program.cs                       ← host setup + TableServiceClient
    ├── host.json / local.settings.json
    ├── Functions/GenerateTaxCertificate.cs
    ├── Functions/ProjectUpdateLog.cs
    ├── Models/…
    └── GiftOfTheGivers.Functions.postman_collection.json
```

## A.1 – The Function Project

### Functions

| Function | Method + route | What it does |
|---|---|---|
| `GenerateTaxCertificate` | `GET` / `POST /api/certificates` | When a donor completes the donation form, generates a **dummy tax certificate** (certificate number, SA tax year, placeholder Section 18A ref, certificate text). `?format=html` returns a printable certificate. |
| `LogProjectUpdate` | `POST /api/project-updates` | When an employee posts a project update, **logs it to Azure Table Storage** (table `ProjectUpdateLog`). |
| `GetProjectUpdateLog` | `GET /api/project-updates?take=10` | Reads the newest entries back from Azure Table Storage. |

All use `AuthorizationLevel.Function`: no key is needed locally, and in Azure you pass `?code=<key>` or an `x-functions-key` header.

### How it connects to the web app

* `Program.cs` (web) registers a typed `HttpClient` → `AzureFunctionsClient`, configured from:
  ```json
  "AzureFunctions": {
    "BaseUrl": "http://localhost:7071/api/",
    "FunctionKey": ""
  }
  ```
* **Donation flow:** Donation form → saved to SQL → redirect to `/Donation/Certificate/{id}` →
  `CertificateModel.OnGetAsync` calls `GenerateTaxCertificateAsync(donation)` → the certificate page shows the function's
  certificate number, tax year and “Generated by Azure Function: GenerateTaxCertificate”. The PDF download uses the same number.
* **Employee update flow:** Dashboard “Post update” → saved to SQL → `LogProjectUpdateAsync(update)` → function writes a row
  to Azure Table Storage. The success banner says “…and logged to Azure Storage”. A new **“Azure Storage update log”** card on the
  dashboard lists the entries read back through `GetProjectUpdateLog`.
* If the Function App is offline, the web app keeps working: it falls back to its own certificate number and shows a message.

### Key code snippets (for the report)

`GiftOfTheGivers.Functions/Functions/GenerateTaxCertificate.cs`
```csharp
[Function(nameof(GenerateTaxCertificate))]
public async Task<IActionResult> Run(
    [HttpTrigger(AuthorizationLevel.Function, "get", "post", Route = "certificates")] HttpRequest req)
{
    var request = HttpMethods.IsPost(req.Method)
        ? await JsonSerializer.DeserializeAsync<TaxCertificateRequest>(req.Body, JsonOptions)
        : FromQuery(req.Query);
    ...
    var certificate = BuildCertificate(request, DateTime.UtcNow);
    return new OkObjectResult(certificate);
}
```

`GiftOfTheGivers.Functions/Functions/ProjectUpdateLog.cs`
```csharp
[Function("LogProjectUpdate")]
public async Task<IActionResult> LogProjectUpdate(
    [HttpTrigger(AuthorizationLevel.Function, "post", Route = "project-updates")] HttpRequest req)

    ...

    return new ObjectResult(ToDto(entity)) { StatusCode = StatusCodes.Status201Created };
}
```

## A.2 – Run and test locally

1. Open `gift_of-the_givers.slnx` in Visual Studio 2022 (with the **Azure development** workload installed).
2. Right-click the solution → **Configure Startup Projects…** → **Multiple startup projects** → set both
   `gift_of-the_givers` and `GiftOfTheGivers.Functions` to **Start**.
3. Press **F5**. Visual Studio starts **Azurite** (local Azure Storage emulator) and the Functions host.
   The console window lists:
   ```
   GenerateTaxCertificate: [GET,POST] http://localhost:7071/api/certificates
   GetProjectUpdateLog:    [GET]      http://localhost:7071/api/project-updates
   LogProjectUpdate:       [POST]     http://localhost:7071/api/project-updates
   ```
   The web app opens on `http://localhost:5275`.

### Browser tests
* `http://localhost:7071/api/certificates?donationId=12&donorName=Thandi%20Mokoena&amount=750&currency=ZAR` → JSON certificate
* `http://localhost:7071/api/certificates?donationId=12&donorName=Thandi%20Mokoena&amount=750&currency=ZAR&format=html` → printable certificate
* `http://localhost:7071/api/project-updates?take=10` → entries stored in Azure Table Storage

### Postman tests
Import `GiftOfTheGivers.Functions/GiftOfTheGivers.Functions.postman_collection.json`
(`baseUrl` = `http://localhost:7071/api`). Run the requests in order:

| # | Request | Expected |
|---|---|---|
| 1 | POST certificate (JSON) | `200 OK` + certificate JSON (`GOTG-TC-2026-000012`) |
| 2 | GET certificate `format=html` | `200 OK` + HTML certificate |
| 3 | POST certificate with amount 0 | `400 Bad Request` – “Amount must be greater than zero.” |
| 4 | POST project update | `201 Created` + stored table entity |
| 5 | GET project update log | `200 OK` + list including the entry from #4 |

### End-to-end test through the web app
* Make a donation → the certificate page shows “Generated by: Azure Function: GenerateTaxCertificate”.
* Log in as the employee → post an update → banner “…logged to Azure Storage”; the entry appears in “Azure Storage update log”.
* Optional: open **View → Cloud Explorer / Azure Storage Explorer → Emulator → Tables → ProjectUpdateLog** to show the row.

**Screenshots for A.2:** Functions console with the three URLs, the browser JSON/HTML responses, each Postman request/response, the
certificate page, the dashboard log card and the Table Storage row.

## A.3 – Deploy the Function to Azure

1. Right-click **GiftOfTheGivers.Functions** → **Publish…** → **Azure** → **Azure Function App (Windows)** → **Next**.
2. Sign in, select your subscription, click **+ Create new**:
   * Name: e.g. `gotg-functions-<studentnumber>` (must be globally unique)
   * Runtime: **.NET 8 Isolated**
   * Resource group: `RSG-RCGPBR-ST10454956-SANORTH` (same as the web app)
   * Plan type: **Consumption**, Location: same region as the web app
   * Azure Storage: create a new storage account (used by the host **and** for the `ProjectUpdateLog` table)
   * Click **Create**, then **Finish**.
3. Click **Publish**. The output window ends with `Publish Succeeded`, which is your deployment screenshot.
4. In the Azure portal open the Function App → **Functions** → `GenerateTaxCertificate` → **Get function URL** → copy the
   *default (function key)* URL. It looks like:
   ```
   https://gotg-functions-<studentnumber>.azurewebsites.net/api/certificates?code=<key>
   ```
   Add `&donationId=12&donorName=Test&amount=500&format=html` to it and open it in a browser. That is your **live function URL**.
5. Connect the deployed web app to the deployed functions: App Service `giftofthegivers2026` → **Settings → Environment variables** → add
   * `AzureFunctions__BaseUrl` = `https://gotg-functions-<studentnumber>.azurewebsites.net/api/`
   * `AzureFunctions__FunctionKey` = the Function App's **App keys → default** key

   Save, then re-publish the web app if needed.
6. Re-run the Postman collection with `baseUrl` = `https://gotg-functions-<studentnumber>.azurewebsites.net/api` and
   `functionKey` = the default key.

account (Storage browser → Tables).
